### USDC Tab: not deployed

A Tab instance holds one token, fixed in its constructor. A second Tab for USDC
needs more than a configuration value in the deployment tool:

- a fourth contract entry (for example `tab-usdc`) in `CONTRACTS`,
  `WASM_FILES`, the constructor arguments, the read-back checks and the
  evidence table, reusing the uploaded Tab Wasm;
- USDC limits in token units (`max_balance`, `min_deposit`) instead of the XLM
  values;
- the extend, restore and redeploy tools and the TTL entry registry for the
  new instance, which today cover exactly Core, Tab and NFT;
- on the app side, one Tab contract per token (`TAB_CONTRACT_ID` is a single
  value), so the indexer, the settler and tab acceptance would also need a
  token-to-Tab mapping.
