# R. Frontend rebuild

The whole product experience is rebuilt on a new application shell with its own navigation, design system
and components, in new directories. Old pages are replaced and deleted, never restyled, and nothing new is
mounted inside the old chrome. The money layer of slice 1 (PR 561) is kept as the foundation: its Convex
queries, hooks, runtime, outbox and tests.

Part 1 is the inventory of the current frontend, the data seam per product area, how the old and new
shells coexist and in what order the old one is removed, and the guard rails. Part 2 maps the product
structure onto the code and splits the build into packages.

Rules this document refers to by name:

| Rule              | Meaning                                                                                                                                                                                                                                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reading rule      | Public reading works without scripts: the home, an article, a writer's page and a shared line are rendered on the server with their content in the first response, with no loading boundary above the reading content; a no-script reading test runs in Chromium and WebKit for each public route |
| Money labels      | A money label means exactly what it says at any history length; pending stays apart from spendable and available ([document 2](02-instant-state.md#26-earnings))                                                                                                                                  |
| Tip rules         | One labelled tip button with a visible amount choice, by tap and keyboard; no swipe pays; a tip does nothing else; no reversal after acceptance ([document 1](01-tip-pipeline.md#12-the-sheet))                                                                                                   |
| Changed lines     | A shared line that the author changed or removed is never shown again                                                                                                                                                                                                                             |
| Signed-in readers | Only signed-in readers count as readers; other tips count as tips                                                                                                                                                                                                                                 |
| v3 contracts only | No v3 transaction reaches a v2 contract ([work packages](work-packages.md#rules-for-every-package))                                                                                                                                                                                               |

## 0. Decisions in one place

| #   | Decision                                                                                                                                                                                                                                                                                                                                                                              | Rejected alternative                                                                                                                                                                                                                                                                                                                          |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **Two root layouts.** All current routes move, unchanged, into a route group `app/(legacy)/` whose `layout.tsx` is today's root layout (globals.css, the old provider tree). The new shell is a second route group `app/(app)/` with its own root `layout.tsx`, its own CSS entry and its own providers. `app/layout.tsx` is deleted. URLs do not change (groups are not in the URL). | One root layout with the new shell nested inside: `globals.css`, the Tailwind base, the old fonts and the old providers would apply to every new page, and CSS loaded by a layout stays in the document across client navigation. A separate app on a subdomain: splits the auth token's storage origin, the CSP, the deploy and the sitemap. |
| R2  | **A surface moves in one pull request:** the new route under `app/(app)/`, the deletion of the old route under `app/(legacy)/`, its components, CSS, hooks that only it used, e2e specs, fixtures and budget entries. The same URL never exists in both groups.                                                                                                                       | Feature flags that serve both: two live versions double the test surface and the old one is never deleted.                                                                                                                                                                                                                                    |
| R3  | **Navigation between the groups is a full page load** (Next.js reloads across root layouts). Accepted while both exist: auth (Convex Auth token in `localStorage`), the payments outbox, the remembered wallet and the intent all survive a reload by design. Each replacement reduces the crossings; the last one removes them.                                                      | Client navigation across both: impossible across root layouts, and the reason R1 isolates styles.                                                                                                                                                                                                                                             |
| R4  | **Logic is kept, presentation is not.** Every Convex function, every `lib/` module that is pure, and every hook that returns data without markup is kept and imported by the new UI. Logic that lives inside old components is extracted into `hooks/<area>/` or `lib/<area>/` in the package that replaces that component, before the component is deleted.                          | Rewriting data access with the UI: the money layer and the ledger have tests and review history that a rewrite would throw away.                                                                                                                                                                                                              |
| R5  | **Dead code goes first**, in one pull request with no behaviour change, so the inventory the packages work from is the live one.                                                                                                                                                                                                                                                      | Deleting it surface by surface: dead files have no surface.                                                                                                                                                                                                                                                                                   |
| R6  | **Merges from `overhaul/v2` after a deletion keep the deletion.** A modify/delete conflict on a deleted presentation file is resolved by deleting; the v2 change is logged and checked for behaviour the new surface must carry (section 3.5). Changes to kept logic merge normally.                                                                                                  | Porting every v2 UI fix into the new code: most are styling or copy for screens that no longer exist.                                                                                                                                                                                                                                         |

## 1. Inventory

Fates:

- **Keep** (logic): the new UI imports it, named.
- **Extract**: logic inside an old component; it moves to the named module in the replacing package.
- **Delete with S**: presentation, removed by the package that ships surface S's replacement.
- **Dead**: imported by nothing; removed in the first pull request (R5).
- **v1**: v1 payment code, removed by the v1 removal work on its own schedule; listed so no package depends
  on it.

1. **Before a surface is deleted:** v2 changes to its files merge normally. Route files moved by the split
   follow `git`'s rename detection.
2. **After a surface is deleted:** a modify/delete conflict on a deleted presentation file is resolved by
   deleting (`git rm`). The merge commit's message lists each dropped v2 change by pull request number, and
   the merger adds a line to `docs/architecture/v3/rebuild-merge-log.md`: the pull request, the files, and

   are checklist items for the surface's owner.
3. **Kept logic** (`hooks/`, `lib/`, `convex/` modules marked Keep) merges normally, always.
4. **A guard against resurrection:** `scripts/rebuild/deleted-paths.txt` lists every deleted path, appended

   brings a deleted file back fails the check.

### 3.6 The deletion rule

A surface's old code is deleted in the same pull request that ships its replacement: the route, its
components and their CSS, hooks and `lib/` modules only it used, its e2e specs and fixtures, its fixture
suite entry, its budget entries and its `proxy.ts` font preloads. A pull request that adds a new surface
without deleting the old one is not merged. Nothing new is mounted inside `(legacy)`.

# Part 2. Work packages on the new shell

## 5. The structure mapped onto the code

### 5.0 The product structure

Three places and a balance. The bar has four items: **Today** (`/`, read), **Shelf** (`/shelf`, keep),
**Write** (`/write`, make), and the **balance**, labelled with the live amount or "Sign in". The balance is
not a place: it opens the **Pocket** as a sheet over whatever the person is doing, and every money act and
the sign-in are sheets that never navigate away from reading. Today opens on an article already underway,
in plain server HTML, with one row each for "Your place" and "Your draft" for a returning person, then a
finite mix of articles and paid lines that ends. Articles, a shared line (`/p/<code>`), a writer's page,
search (`/search`), the editor (`/write/<id>`), "You" (`/you`) and today's lines (`/lines`) are pushed
screens with their own URLs. There is no dashboard, no inbox, no landing film, no tip dialog, no wallet
page and no stats page: each notice lands where it belongs (a dot on the place that changed). On desktop
the bar is a left rail and the Pocket a right-hand panel.

### 5.1 URLs and reserved handles

- Canonical URLs stay `/{username}/{slug}` (article) and `/{username}` (writer page) .
  `/@handle` is an alias: `proxy.ts` answers it with a 308 to `/{username}` (a folder named `@…` would be a
  parallel-route slot in Next.js, so it cannot be a route). `/a/<slug>` is not used.
- New top-level paths: `/shelf`, `/write` (exists), `/write/<id>`, `/p/<code>`, `/lines`, `/search`, `/you`,
  `/pocket`, `/signin`. The split pull request adds all of them to `APP_ROUTE_SEGMENTS` at once, so no
  later package edits that list. `p` cannot be a handle (shorter than 3 characters); the others become
  reserved through `handleFormatError`, which already refuses every `APP_ROUTE_SEGMENTS` entry.
- **Existing users holding one** (`shelf`, `lines`, `search`, `you`, `pocket`, `signin`): before the
  segments ship, `handles.findReservedCollisions` (internal query over `users.by_username_lower` and
  `usernameHistory.by_username_lower`) lists them. For each current holder,
  `handles.retireReservedHandle({ userId })` (internal mutation) renames the user to the first free
  `<handle>_<n>`, records the old handle in `usernameHistory` (so `/@<old>` still finds them), and sets
  `users.handleNotice = 'reserved'`, which You shows once ("Your handle changed to you_1 because /you is now
  a Quilltip page. You can choose another."). Their article links `/{old}/{slug}` would now hit an app
  route, so the redirect table (5.4) gets one generated entry per retired handle:
  `/{old}/{slug}` → `/{new}/{slug}`. A retired-history entry (not a current holder) only loses its old
  redirect. NFT metadata keeps the old URL; the redirect covers it. Tests: a collision on each reserved
  word; a history-only collision; the generated redirect.
