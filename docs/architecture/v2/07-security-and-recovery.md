# 7. Security and recovery

[Index](../v2-spec.md)

## 7.1 Invariants

Tests cite these IDs ([section 8.1](08-testing-and-deployment.md#81-test-plan)).

### Core

| ID  | Invariant                                                                                                                                                                                                |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I-1 | For every tip, `fee == floor(gross × 250 / 10,000)` and `fee + Σ shares == gross`.                                                                                                                       |
| I-2 | Recipients together receive `gross − fee`. Each non-primary recipient receives `floor(net × bps / 10,000)`. The primary author receives the remainder. No transfer is made for a zero share.             |
| I-3 | `article_total(article, token)` grows by exactly `gross` per successful tip and never decreases.                                                                                                         |
| I-4 | A tip fails if Core is paused, or if any of these holds: the token is not allowed; `amount <= 0`; `amount < min_tip`; the article is not registered; the tipper is a recipient.                          |
| I-5 | A `(tipper, client_ref)` pair succeeds in at most one Core tip within `TIP_REF_TTL`.                                                                                                                     |
| I-6 | Core never holds tokens. No call changes Core's token balance.                                                                                                                                           |
| I-7 | Only the stored author can update content or splits, and the author must authorise it. An author change needs a proposal by the old author and acceptance by the new author before the proposal expires. |
| I-8 | Stored splits always satisfy the split rules ([section 2.1](02-core-contract.md#21-types)).                                                                                                              |
| I-9 | `tip_batch` is atomic. It enforces both caps and emits exactly one `Tipped` per item.                                                                                                                    |

### Tab

| ID   | Invariant                                                                                                                                                                               |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I-10 | Conservation: the Tab's token balance equals Σ `ReaderAccount.balance` plus Σ `Claimable`.                                                                                              |
| I-11 | For each `(reader, key_id, writer)`, `Paid` never decreases and never exceeds the largest validly signed `cumulative`.                                                                  |
| I-12 | A settlement moves at most `min(delta, balance, spend_limit − spent)`.                                                                                                                  |
| I-13 | Each settlement splits `gross` into `fee` for the treasury's claimable balance and `gross − fee` for the writer's claimable balance, with `fee` computed by the cumulative rule (I-31). |
| I-14 | A voucher verifies only for its own network, Tab contract, reader, writer, key ID, public key and cumulative amount.                                                                    |
| I-15 | No voucher settles under a key after `valid_until + SETTLE_GRACE`.                                                                                                                      |
| I-16 | `withdraw` succeeds only when at least `WITHDRAW_DELAY` has passed since `withdraw_start`. It pays exactly the balance, and only to the reader.                                         |
| I-17 | `claim` pays exactly the claimable amount, only to the recipient, and leaves the claimable amount at zero.                                                                              |
| I-18 | `settle_own` settles a voucher only with a valid acceptance signature from a key in `acceptor_keys`, and only for the calling writer.                                                   |

### NFT

| ID   | Invariant                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| I-19 | At most one NFT exists per article. Only the Core author mints it, and only while the Core total is at or above the threshold at mint time. |
| I-20 | The royalty is 1,000 bps to the minting author, set at mint and never changed afterwards.                                                   |

### Application

| ID   | Invariant                                                                                                                                                                                                                                                                    |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I-21 | A payment record becomes `CONFIRMED` or `MISMATCH` only by the rule in [section 6.1](06-app-integration.md#61-transaction-lifecycle). Client input never sets either state.                                                                                                  |
| I-22 | A tab receipt is `ACCEPTED` only when all of these hold: a valid session signature; the next `seq`; `cumulative == previous + amount`; `outstanding + amount ≤ confirmedBalance`; the amount fits within the key limit and the Convex limits; and the article has no splits. |
| I-23 | Identifier, canonical article, voucher, acceptance and Merkle encodings match across Rust, Convex and the client for every shared test vector.                                                                                                                               |
| I-24 | A record becomes `EXPIRED` only after the indexer has covered every ledger up to `maxTime`. A record whose transaction RPC reports as `SUCCESS` never becomes `FAILED`. The UI offers a retry only for `FAILED` and `EXPIRED`, never for `MISMATCH`.                         |

### All contracts

| ID   | Invariant                                                                                                                                                                               |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| I-25 | After any state-changing call, the instance and every persistent entry the call wrote have a TTL of at least `TTL_THRESHOLD`.                                                           |
| I-26 | No contract has a public `initialize`. Every admin function enforces its role, and `renounce_admin` always fails.                                                                       |
| I-27 | Pause never blocks `settle`, `settle_own`, `claim`, `revoke_key`, `withdraw_start` or `withdraw`.                                                                                       |
| I-28 | `Account` entries are never removed. `next_key_id` never decreases, including across `migrate`.                                                                                         |
| I-29 | `Session(reader, key_id)` and every `Paid(reader, key_id, *)` stay live at least until `valid_until + SETTLE_GRACE`, the last ledger at which a voucher under that key can be accepted. |
| I-30 | `migrate` runs once per schema version. An upgrade preserves all stored state.                                                                                                          |
| I-31 | For every `(reader, key_id, writer)`, the fees credited sum to `floor(Paid × 250 / 10,000)`.                                                                                            |

## 7.2 Threat model (STRIDE)

| Component         | Threat                                                                                      | Category               | Mitigation                                                                                                                                                                                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core registration | Someone registers another author's article ID to redirect tips                              | Spoofing               | `article_id` derives from the Convex article ID. The prepare check tips only articles whose on-chain author equals the article owner's linked address.                                                                                                                                                    |
| Core tip          | A malicious token contract fakes transfers                                                  | Tampering              | Token allowlist (I-4). SAC addresses only.                                                                                                                                                                                                                                                                |
| Core tip          | A duplicate submission charges twice                                                        | Tampering              | Sequence numbers. `(tipper, client_ref)` deduplication (I-5). The expiry rule and no retry after `MISMATCH` (I-24).                                                                                                                                                                                       |
| Core tip          | A third party front-runs a `client_ref` to block a retry                                    | Denial of service      | `TipRef` is keyed by tipper (I-5).                                                                                                                                                                                                                                                                        |
| Core admin        | The fee is raised silently                                                                  | Elevation of privilege | `FEE_BPS` is a constant. Changing it needs an upgrade.                                                                                                                                                                                                                                                    |
| All, upgrade      | A compromised upgrader or admin key replaces Tab code and moves every balance               | Elevation of privilege | Testnet: one operator key, testnet funds only. Mainnet: an upgrader timelock whose minimum delay exceeds `WITHDRAW_DELAY + 2 days`, so readers can exit before a scheduled upgrade takes effect. Admin is a 2-of-3 multisig ([section 8.5](08-testing-and-deployment.md#85-mainnet-release-differences)). |
| All, admin        | The admin renounces, so a pause becomes permanent                                           | Denial of service      | `renounce_admin` always fails (I-26). Pause never blocks exits (I-27).                                                                                                                                                                                                                                    |
| All, init         | Constructor front-running                                                                   | Elevation of privilege | `__constructor` only (I-26)                                                                                                                                                                                                                                                                               |
| Tab voucher       | A voucher is replayed on another network or contract, or under another key                  | Spoofing               | `domain`, `network_id`, `tab` and `public_key` are in the payload (I-14). Key IDs are never reused (I-28).                                                                                                                                                                                                |
| Tab voucher       | An old voucher is replayed after its state expires                                          | Tampering              | `Paid` is monotonic (I-11) and lives as long as the acceptance window (I-15, I-29).                                                                                                                                                                                                                       |
| Tab session key   | A script in the app origin uses the key handle                                              | Elevation of privilege | Vouchers settle only through Convex acceptance (I-18, I-22). Convex daily and per-tip limits. A smaller default `spend_limit`. Key expiry. Revocation. A CSP with no inline scripts ([section 6.8](06-app-integration.md#68-environment-variables-and-network-guard)).                                    |
| Tab acceptor key  | The acceptor secret leaks                                                                   | Elevation of privilege | The acceptor can only countersign vouchers that the reader also signed, so it cannot move funds alone. `set_acceptor` rotates it. Testnet only. KMS on mainnet.                                                                                                                                           |
| Tab settler       | The settler key leaks                                                                       | Elevation of privilege | The settler can submit only reader-signed vouchers. Revoke the role. Testnet only.                                                                                                                                                                                                                        |
| Tab settler       | The settler withholds or delays settlement, or chooses who is paid first on a short balance | Denial of service      | `settle_own` with downloaded vouchers. Lag alerts. Pause does not block settlement (I-27). The ordering rule is published ([section 3.7](03-tab-contract.md#37-liveness-and-disputes)).                                                                                                                   |
| Tab and Convex    | Convex is unavailable, so writers cannot fetch new vouchers                                 | Denial of service      | Stated dependency. Writers keep the last downloaded voucher. Readers' exit does not need Convex.                                                                                                                                                                                                          |
| Tab reader        | A reader withdraws before writers are settled                                               | Repudiation            | `WITHDRAW_DELAY`. Convex settles closing accounts first.                                                                                                                                                                                                                                                  |
| Tab reader        | A reader signs beyond the balance                                                           | Tampering              | Convex checks the balance (I-22). The contract caps payment at the balance and records the shortfall.                                                                                                                                                                                                     |
| NFT               | A mint happens below the threshold                                                          | Elevation of privilege | The NFT reads the threshold total from Core (I-19). The threshold measures tip volume, not independent support ([section 4](04-nft-contract.md)).                                                                                                                                                         |
| NFT               | The royalty receiver is changed after mint                                                  | Tampering              | The royalty setters always fail (I-20).                                                                                                                                                                                                                                                                   |
| Convex            | A client claims a tip that did not happen                                                   | Spoofing               | RPC verification on the server (I-21)                                                                                                                                                                                                                                                                     |
| Convex            | Prepare endpoints are spammed                                                               | Denial of service      | The existing rate limiter (`convex/lib/rateLimit.ts`) runs on every prepare and submit.                                                                                                                                                                                                                   |
| Indexer           | Events beyond RPC retention are missed                                                      | Repudiation            | Lag alert at 1 h. Backfill script (section 7.4).                                                                                                                                                                                                                                                          |
| All               | Mainnet misconfiguration                                                                    | Tampering              | The network guard also reads the RPC and passphrase variables, and always refuses mainnet in this phase.                                                                                                                                                                                                  |
| All               | Storage growth or archival causes denial of service                                         | Denial of service      | No unbounded collections. TTL policy (I-25). Simulation restores archived entries.                                                                                                                                                                                                                        |

## 7.3 Edge cases

| Case                                                                                                                  | Expected result                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `amount = 0` or negative                                                                                              | Core: `InvalidAmount` (7). Tab `deposit`: `BelowMinimumDeposit` (31). Tab `open_session`: `InvalidAmount` (30) when negative; `0` means no deposit. |
| `amount = min_tip − 1`                                                                                                | `BelowMinimum`                                                                                                                                      |
| `amount = min_tip = 40` with a 1% split recipient                                                                     | The fee is 1. The recipient's share is 0, so it gets no transfer. The primary author receives the remainder.                                        |
| `gross` or a total near `i128::MAX`                                                                                   | `Overflow`. Nothing changes.                                                                                                                        |
| Dust in the Core per-tip split                                                                                        | `fee` rounds down, and the writer side gets the remainder (I-1).                                                                                    |
| Tab fee across many small settlements                                                                                 | The fee follows the cumulative rule, so the total does not depend on how settlements were split (I-31).                                             |
| Self-tip, or the tipper is a co-author                                                                                | `SelfTip`                                                                                                                                           |
| Duplicate `(tipper, client_ref)` the same day, or within a batch                                                      | `DuplicateClientRef`                                                                                                                                |
| Unregistered article                                                                                                  | `NotRegistered`. The app disables the tip button.                                                                                                   |
| The author changed wallet in the app only                                                                             | Prepare refuses with "update the article's payout address". The author runs the propose-and-accept flow.                                            |
| The author changed on chain between prepare and submit                                                                | The tip pays the registered on-chain author. Convex marks the record `MISMATCH`, credits the on-chain recipient, and never offers a retry.          |
| A batch of 11 items, or more than 24 transfers                                                                        | `BatchTooLarge`                                                                                                                                     |
| A token not on the allowlist, or disabled                                                                             | `TokenNotAllowed`                                                                                                                                   |
| A bad signature, a wrong `network_id` or `tab`, an encoding difference, a missing account, or an overflow in `settle` | The whole transaction aborts. The settler's checks, simulation and bisection exclude the failing voucher as `REJECTED`.                             |
| Two vouchers for the same pair in one batch                                                                           | The first settles. The second is skipped as `STALE` unless its cumulative amount is higher.                                                         |
| A voucher after `withdraw`                                                                                            | `gross = 0`, so it is skipped as `SHORTFALL`. Receipts become `UNPAID` once the key window ends.                                                    |
| `register_key` with `valid_until` more than 30 days ahead                                                             | `InvalidKeyExpiry`                                                                                                                                  |
| A deposit while closing                                                                                               | The withdrawal is cancelled.                                                                                                                        |
| A claim with nothing owed                                                                                             | Returns 0, with no transfer.                                                                                                                        |
| A claim to a G-account without a trustline (non-native token)                                                         | The SAC transfer fails and the call reverts. The UI asks the writer to add the trustline.                                                           |
| A second NFT mint                                                                                                     | `AlreadyMinted`                                                                                                                                     |
| A tab tip to an article with splits                                                                                   | Refused at prepare. The reader is offered a direct tip.                                                                                             |

## 7.4 Failure recovery

Every operational script runs from `scripts/contracts/` or `scripts/chain/`.
Each script:

- calls `assertScriptStellarTestnetOnly` when it touches no Convex backend (extend, restore, redeploy), or `assertScriptTestnetOnly` when it writes to Convex (backfill);
- passes the network, RPC URL and passphrase to the Stellar CLI explicitly.

| Failure                   | Detection                                                          | Recovery                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Simulation failure        | `prepareTransaction` throws or returns an error                    | Nothing is submitted. The UI shows the mapped error. The record expires by rule. Transient RPC errors get one automatic retry.                                                                                                                                                                                                                                                                              |
| Expired envelope          | `txTOO_LATE`, or `NOT_FOUND` after indexer coverage of `maxTime`   | Mark the record `EXPIRED`. The user may retry with a new intent and `client_ref`.                                                                                                                                                                                                                                                                                                                           |
| Duplicate submit          | `DUPLICATE` status, or the same `(txHash, clientRef)` twice        | Treat it as `PENDING`. On chain, `DuplicateClientRef` stops a second payment with the same reference.                                                                                                                                                                                                                                                                                                       |
| RPC outage                | Timeouts, or `getHealth` fails                                     | **Client:** shows "network busy" and changes no state. **Convex:** records stay `SUBMITTED`, nothing expires (I-24), and the indexer resumes from its cursor. If the outage lasts more than 1 h, switch `STELLAR_RPC_URL` to a second testnet RPC provider. That provider must already be listed in the CSP `connect-src`.                                                                                  |
| Indexer behind retention  | `lastLedger < oldestLedger`                                        | 1. Set `CHAIN_V2_ENABLED=false`. 2. Run `scripts/chain/backfill-events.ts`. It reads the missed range from an archive RPC provider or a hosted indexer and writes to `chainEvents` through an internal mutation. Handlers are idempotent. 3. Reconcile. 4. Resume. Records that no source can resolve are flagged for manual review.                                                                        |
| Archived contract entries | Simulation returns restore requirements                            | Prepared transactions restore automatically. `scripts/contracts/extend-v2-testnet.ts` extends the instance and Wasm entries weekly. `scripts/contracts/restore-v2-testnet.ts` restores large footprints.                                                                                                                                                                                                    |
| Settler outage            | The oldest due voucher is older than 6 h                           | Alert at 6 h and again at 24 h. Fix and restart, or grant `settler` to a second key or a relayer. Writers can use `settle_own`. Tolerance without writer action is about 2.75 days ([section 3.7](03-tab-contract.md#37-liveness-and-disputes)).                                                                                                                                                            |
| Settler balance low       | Settler account below 50 XLM                                       | Alert. Fund the account from Friendbot (testnet) or the treasury.                                                                                                                                                                                                                                                                                                                                           |
| Session-key loss          | The client has no key, or no local ledger, for an active `key_id`  | Register a new key. Convex keeps settling the old key's accepted vouchers. The user may revoke the old key.                                                                                                                                                                                                                                                                                                 |
| Paused contract           | `chainConfig.paused`, or OpenZeppelin `PausableError` (1000 range) | The UI shows "payments paused" for blocked actions. Settlement, claims and exits continue (I-27).                                                                                                                                                                                                                                                                                                           |
| Testnet reset             | Contract instances are missing, or the ledger sequence drops       | 1. Set `CHAIN_V2_ENABLED=false`. 2. Close the current `chainEpoch`. Unsettled tab receipts become `VOID_RESET`, and the history keeps its labels. 3. Run `scripts/contracts/redeploy-v2-testnet.ts` from the recorded commit ([section 8.4](08-testing-and-deployment.md#84-testnet-deployment-procedure)). 4. Start a new `chainEpoch` and `INDEXER_START_LEDGER`. 5. Prompt authors to enable tips again. |
