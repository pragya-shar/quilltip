# Architecture

QuillTip's main flow is reading/writing articles, saving exact-passage highlights,
and appreciating authors through Stellar tips. Payment development uses testnet;
Arweave publishing is optional and can be permanent.

## Boundaries

| Area                                | Responsibility / source                                                                                                                                                    |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `app/`                              | Next.js App Router pages; public articles use `/{username}/{slug}`, author profiles use `/{username}`, and private work lives under `/dashboard`, `/write`, and `/drafts`. |
| `components/`, `hooks/`             | React UI, editor, reader, wallet interactions; see [component organization](component-organization.md).                                                                    |
| `convex/`                           | Convex Auth, database queries/mutations, verification actions, upload ownership, scheduled jobs. `schema.ts` is the live schema; `_generated/` is generated by Convex.     |
| `lib/stellar/`                      | Browser network/contract configuration, transaction builders, and wallet adapter.                                                                                          |
| `contracts/tipping/`                | Soroban article/highlight tipping and batch settlement, including author/platform fee distribution.                                                                        |
| `contracts/article-nft/`            | Soroban article NFT contract.                                                                                                                                              |
| `lib/arweave/`, `convex/arweave.ts` | Permanent article payload upload and confirmation.                                                                                                                         |

Use `package.json` for the stack/dependency inventory rather than a second version
list. UI includes Tiptap and Tailwind; backend functions use Convex validators at
API boundaries. Reuse local UI patterns and preserve their existing CSS/motion
choices rather than imposing a different component library.

## Data and trust

- `convex/schema.ts` defines articles/drafts, users, highlights, tip intents and
  transaction records, earnings, NFTs, uploads, and related metadata. Check the
  schema and the actual function when changing a field or index.
- Authenticated identity and ownership are enforced in Convex, including upload
  tickets/owners/references. Client visibility is not authorization.
- Tip preparation and verification must agree on account, contract, network,
  asset, amount, and intent. A wallet success display alone does not prove a
  confirmed/accounted tip; inspect backend state and the ledger when relevant.
- `convex/crons.ts` schedules recovery, reconciliation, intent cleanup, and price
  refresh. Inspect each action's flags before invoking it manually.
- Arweave publication schedules a backend upload and later verification. Review
  the actual enablement and wallet configuration before testing this path.
